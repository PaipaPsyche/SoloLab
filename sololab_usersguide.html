SoloLab User Guide

A plain-language walkthrough for people who have never used SoloLab before - no assumed programming experience.

This guide has two parts: getting SoloLab running on your computer (Windows, macOS, or Linux), and using the app once it's open. If you get stuck anywhere, the Getting help section at the end tells you exactly what to do.

1. What is SoloLab?

SoloLab is a program for looking at data from Solar Orbiter, a spacecraft that studies the Sun. It reads data files from three of the spacecraft's instruments - STIX (X-rays), RPW (radio waves), and EPD (energetic particles) - and turns them into plots you can look at, zoom into, and compare side by side. Its main job is helping you see how an event (like a solar flare) shows up across all three instruments at the same time.

You do not need to know how to write computer code to use SoloLab. You will type a small number of commands to install it (copy-paste, one line at a time), and after that everything is done by clicking buttons in a normal web page.

2. Which version should I use?

SoloLab actually comes in two forms that do largely the same thing:

Web app (recommended)Desktop app
What it looks like Opens in your normal web browser (Chrome, Firefox, etc.) A separate application window
Best for Most people - it has the newest features, including automatic background estimation and combined multi-instrument plots People who specifically prefer a desktop-style window, or need a feature only it has (STIX background-file subtraction with manual energy shifts)

This guide focuses on the web app, since that's what most people should start with. Both apps read the same kind of data files.

3. Installing SoloLab

New to using a terminal? A "terminal" (also called "command line", "PowerShell", or "Terminal.app") is a plain text window where you type commands instead of clicking icons. It looks intimidating the first time but you will only ever need to copy a line from this guide and paste it in, one at a time, pressing Enter after each. Nothing here can damage your computer if typed correctly.

Step 1 - Install Python (skip if you already have it)

Open a terminal and type:

# Windows
python --version

# macOS / Linux
python3 --version

If that prints something like Python 3.11.4 (any 3.10, 3.11, or 3.12), you already have it - skip to Step 2. Otherwise:

WINDOWS

Go to python.org/downloads/windows, download the latest "Windows installer (64-bit)" for Python 3.12, run it, and make sure to check the box that says "Add python.exe to PATH" on the very first screen before clicking Install. This step is the one people most often miss - if you forget it, typing python later won't work. No admin rights are needed if you choose "Install for me only".

MACOS

Easiest way: install Homebrew first (a one-time copy-paste command shown on that site), then run:

brew install python@3.12

Without Homebrew, download the installer from python.org/downloads/macos instead.

LINUX
sudo apt update
sudo apt install python3 python3-venv python3-pip

(Fedora/RHEL: sudo dnf install python3 python3-pip. Arch: sudo pacman -S python python-pip.)

Step 2 - Download SoloLab

If you were given a folder or a ZIP file, unzip it anywhere convenient (like your Desktop or Documents folder) and open a terminal inside that folder:

  • Windows: open the folder in File Explorer, click the address bar, type powershell, press Enter.
  • macOS: open the folder in Finder, right-click it, choose "New Terminal at Folder" (or drag the folder onto the Terminal app icon).
  • Linux: right-click inside the folder in your file manager and look for "Open Terminal here".

If instead you're comfortable with git, you can clone it:

git clone https://github.com/PaipaPsyche/SoloLab.git
cd SoloLab

Step 3 - Set up SoloLab's own space (a "virtual environment")

This keeps SoloLab's files separate from anything else on your computer, so it can't break other programs. Copy-paste these commands one at a time, in the terminal you just opened, still inside the SoloLab folder:

WINDOWS
python -m venv .venv-dash
.venv-dash\Scripts\python.exe -m pip install --upgrade pip
.venv-dash\Scripts\python.exe -m pip install -r requirements-dash.txt
If Windows says something like "running scripts is disabled on this system", that's fine - the commands above never need to "activate" anything, so you won't hit that message with them.
MACOS / LINUX
python3 -m venv .venv-dash
.venv-dash/bin/python -m pip install --upgrade pip
.venv-dash/bin/python -m pip install -r requirements-dash.txt

This step downloads everything SoloLab needs and can take a few minutes the first time - that's normal, just let it finish.

Step 4 - Check everything installed correctly

# Windows
.venv-dash\Scripts\python.exe test_installation.py

# macOS / Linux
.venv-dash/bin/python test_installation.py

You should see a list of packages with [OK] next to each one, ending with Overall: PASS. If something says PASS is not shown, see Common problems below, or the full INSTALL.md file, which covers more edge cases than this guide.

4. Starting the app

# Windows
.venv-dash\Scripts\python.exe -m sololab.dash_app.app

# macOS / Linux
.venv-dash/bin/python -m sololab.dash_app.app

The terminal will print something like Running on http://127.0.0.1:8050. Open that address in your web browser (copy http://127.0.0.1:8050 and paste it into Chrome, Firefox, Safari, or Edge). That's SoloLab - you should see its home page.

Leave the terminal window open while you use the app - it's quietly running the program behind the scenes. Closing the terminal closes SoloLab. To stop it on purpose, click into the terminal and press Ctrl+C.

5. Using the web app, step by step

The sidebar on the left is how you get everywhere: Import Data to load an instrument's data, Data Pack to save/reload a session, and under Plot, Plot Data (one instrument at a time) or Combined Plot (several instruments stacked together).
Step A - Import data. Click Import Data, then pick an instrument (STIX, RPW-HFR, RPW-TNR, or EPD). Each instrument's page gives you two ways to get data in:
  • Upload a file you already have, by dragging it into the dashed box.
  • Download it directly - STIX and RPW can search their own online data archives for you (pick a date/time and how far to search), so you don't need to hunt for a file yourself. EPD downloads automatically for whatever day you type in.
Once a file is selected, click Preview Data (or Plot Preview for EPD) to check it looks right before continuing.
Step B - Subtract a background (optional). After previewing, a Background section appears. This removes a "quiet" baseline level from your data so real events stand out more. Tick the box, choose a time range from your own data that you know was quiet (no flares/bursts), pick how that quiet period should be summarized (the "polling function" - mean or median are the usual choices), then click Preview with Background Subtraction to see the result before committing to it.
Step C - Load it. Click LOAD. The instrument's badge in the sidebar turns green, meaning it's ready to plot. Repeat Steps A-C for any other instruments you want.
Step D - Plot a single instrument. Click Plot Data in the sidebar, pick the instrument's tab, choose spectrogram (a color map of intensity over time and energy/frequency) or time profiles (simple line plots), and click the matching Plot Preview button.
Step E - Combine instruments. Click Combined Plot, then Select instruments to plot and tick whichever ones you've loaded. Use the up/down arrows to choose which one appears on top vs. bottom - they all share one time axis, stacked vertically, so you can directly compare when things happened across instruments. Click PLOT.
Step F - Save your work. Click Data Pack and then Save Data Pack to download everything you've loaded as one file. Next time, open Data Pack again and drop that file into the Load box to get straight back to where you left off, without re-downloading anything.

6. Common problems

You see...What it means / what to do
python: command not found (or similar) Python isn't installed, or (Windows) "Add to PATH" wasn't checked during install - see Step 1 again.
An error trying to compile/build something during Step 3 You likely have a very new Python version some packages don't support yet. Reinstall using Python 3.12 specifically.
ModuleNotFoundError: No module named 'PyQt5' Expected and harmless for the web app - it doesn't need PyQt5.
"Downloading STIX data requires the optional 'stixdcpy' package" Only appears if you click a "download" button without that one extra package. Run: .venv-dash\Scripts\python.exe -m pip install stixdcpy (or the macOS/Linux equivalent) and try again.
The browser page never loads / "This site can't be reached" Check the terminal is still open and didn't print an error. Make sure you typed http://127.0.0.1:8050 exactly.

More edge cases are covered in INSTALL.md's own Troubleshooting section.

7. Getting help

If something in this guide doesn't work, or doesn't match what you see on screen, that's useful information - please don't just give up on it. Contact david.paipa@obspm.fr with:

  • which operating system you're using (Windows / macOS / Linux),
  • which step you were on, and
  • the exact text of any error message (a screenshot is perfect).

You can also open an issue on GitHub if you're comfortable doing so.
